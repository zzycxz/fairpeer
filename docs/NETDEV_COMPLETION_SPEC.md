## §0 全景诊断

R1–R5 五批交付后，运维界面的问题不是「缺功能」，而是三类结构性错位：

| 类别 | 定义 | 典型样本 | v1.1 状态 |
|---|---|---|---|
| **断链** | 桥两端有一端没做完，用户看得见入口却走不通 | ~~终端按钮只 Start 不渲染~~；CVE Sweep 无 feed 断头路 | 大半已修（§2） |
| **深埋** | 能力已接线，但入口藏在页签角落/设置深层 | 报告族三件藏在审计页；nmap 导入在「高级」子页签 | 场景卡已扩容（§3.2 ✅），其余在途 |
| **闭环断裂** | 动作有入口，结果无归处、无下一步 | 四个全网动作的成功结果写进 `banner--error`（NetDevLayout.tsx:659/716） | ⬜ 未动（§3.1） |

另有一批 **R4/R5 spec 承诺但未交付** 的项（§6），裁决表已执行大半。

## §1 范围

**做**（四批，C1–C4）：
- C1 断链收尾——五条「有入口走不通」的链路（§2）
- C2 引导层重建——结果归位 + 场景卡扩容 + 对话引导 + 断头路 signpost（§3）
- C3 面板能力补全——提案驳回、导出体系、健康明细、i18n 等（§4）
- C4 后端能力接线——发现按钮、弱口令字典档、bot 闭环、netconf 入口（§5）

**不做**（维持 NETDEV_SPEC v2.1 §八「按需停车场」边界，启动条件触发再立项）：
分域纳管/CSV 批量导入、gNMI、sFlow/NetFlow、GPU 数据面、BGP/RPKI/光层、
拓扑人工覆盖层、有界抓包、DB 参数基线/DDL 评估/迁移演练、二次升级（分域值班表）。

**安全不变量（全程不可妥协，写在这里供每条方案自检）**：
1. 诊断能力结构性只读——写/危险命令一律拒执行并落审计；写路径唯一入口是提案（人工签核）。
2. 凭证只进加密密钥库，绝不进 TOML/导出包/日志。
3. 每条设备命令（含拒绝、含人工终端）落审计哈希链。
4. 探测范围白名单与设备组作用域是「永不关闭的护栏」，任何新入口（含 C4 发现按钮）必须先过同一套校验。
