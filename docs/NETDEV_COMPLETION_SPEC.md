## §0 全景诊断

R1–R5 五批交付后，运维界面的问题已不是「缺功能」，而是三类结构性错位：

| 类别 | 定义 | 典型样本 |
|---|---|---|
| **断链** | 桥两端有一端没做完，用户看得见入口却走不通 | 终端按钮只 Start 不渲染（NetDevLayout.tsx:1075）；SFTP 桥零调用 |
| **深埋** | 能力已接线，但入口藏在页签角落/设置深层，靠运气发现 | IP 定位输入框在清单页签顶部；报告族三件藏在审计页；nmap 导入在「高级」子页签 |
| **闭环断裂** | 动作有入口，结果无归处、无下一步 | 四个全网动作的成功结果写进 `banner--error`（NetDevLayout.tsx:607/621/664/688） |

另有一批 **R4/R5 spec 承诺但未交付** 的项（§六），需要逐条裁决「补做 / 降级 / 明确砍掉」，
而不是无限期挂在原 spec 的验收表里。

---

## §1 范围

**做**（四批，C1–C4）：
- C1 断链收尾——五条「有入口走不通」的链路（§二）
- C2 引导层重建——结果归位 + 场景卡扩容 + 对话引导 + 断头路补signpost（§三）
- C3 面板能力补全——提案驳回、导出体系、健康明细、i18n 等（§四）
- C4 后端能力接线——发现按钮、弱口令字典档、bot 闭环、netconf 入口（§五）

**不做**（维持 NETDEV_SPEC_V2 §8 立项边界，另行评审）：
R6 战略批全体（分域纳管/CSV 批量导入、gNMI、sFlow/NetFlow、GPU 数据面、BGP/RPKI/光层、
拓扑人工覆盖层、有界抓包、DB 参数基线/DDL 评估/迁移演练）。

**安全不变量（全程不可妥协，写在这里供每条方案自检）**：
1. 诊断能力结构性只读——写/危险命令一律拒执行并落审计；写路径唯一入口是提案（人工签核）。
2. 凭证只进加密密钥库，绝不进 TOML/导出包/日志。
3. 每条设备命令（含拒绝、含人工终端）落审计哈希链。
4. 探测范围白名单与设备组作用域是「永不关闭的护栏」，任何新入口（含 C4 发现按钮）必须先过同一套校验。

## §2 C1 断链收尾（P0，约 1 周）

### 2.1 人工终端前端渲染

**现状**（复核后）：后端全链路已通——`HumanTTYStart/Write/Stop/Status/Resize` +
`netdev:humantty` 输出事件 + `saveHumanTTYRecording` 脱敏录制（humantty.go:200/:222/:316）；
bridge 已封装 `onNetdevHumanTTY`（bridge.ts:873）；`@xterm/xterm@6` 已在依赖中。
**缺口**：设备卡「⌨ 终端」按钮只调 Start 并提示「已连接（xterm 渲染随下批）」
（NetDevLayout.tsx:1071-1079）；`Write/Stop/Resize` 桥声明零调用；事件零订阅。

**方案**：
- 复用既有 `TerminalSession.tsx`（本地 ConPTY 已在用）+ `terminalNode` 插槽
  （CoWorkLayout.tsx:282 / App.tsx:3229）挂 xterm 实例，订阅 `onNetdevHumanTTY` 按 device 分流；
- 键入 → `NetDevHumanTTYWrite`；窗口尺寸变化 → `NetDevHumanTTYResize`；关闭页签/离开运维模式 →
  `NetDevHumanTTYStop`（防孤儿会话）；红色紧急停止按钮现调 `NetDevEmergencyStop`
  （NetDevLayout.tsx:60）须在 UI 文案中明示「同时杀人工终端」；
- 多设备多会话：每个设备一个终端页签，会话列表显示 `NetDevHumanTTYStatus`（在飞字节/时长）；
- 编码跟随设备配置（gbk 设备沿用后端 streamDecoder，前端不做转码）。

**验收**：设备卡点终端直接敲命令有回显；开两台设备两个终端互不串流；关页签后台会话即断；
审计页能看到该会话起止与字节量；紧急停止后终端立即死掉并提示。

### 2.2 SFTP 只读文件浏览器

**现状**（复核后）：后端 App 方法已就绪（NetDevSFTPDownload netdev_app.go:1626 /
NetDevSFTPBrowse :1654，白名单 + 审计）；bridge 已声明 + mock（bridge.ts:511-512）。
**缺口**：全前端零调用——无浏览/下载 UI。

**方案**：设备卡新增「📁 文件」按钮（仅 linux/windows 与 kind=docker 主机显示）→
L3 面板式文件浏览器：目录列表（Browse）+ 单文件下载（Download，落盘位置用户选择，
显示后端大小上限）；下载完成 toast 给出路径；每次浏览/下载进审计。上传继续只存在于提案步骤，不做 UI。

**验收**：从设备卡 3 次点击内取到 `/var/log/nginx/error.log` 本地副本；
白名单外路径被拒并给出可读原因；审计页能查到该次下载。

### 2.3 CVE 链路前半段

**现状**：`NetDevImportCVEs`（feed 导入）与 `NetDevCVEMatches`（命中列表）桥声明完整但零组件调用；
发现页签的 Sweep 按钮在没有 feed 时是断头路。

**方案**：安全工作台（SecWorkbench）新增「CVE」区：导入 feed（粘贴/选文件）→ 匹配清单表
（设备 × CVE × 严重度 × 命中证据）→ 一键 Sweep；Sweep 空结果时文案引导「先导入 feed」。

**验收**：「这台 IOS 有哪些 CVE」从导入 feed 到命中表全程 GUI 完成，无需读文档。

### 2.4 Trap 接收器状态回显

**现状**：`NetDevTrapStatus` 零调用；syslog 有状态行（NetDevSection.tsx:107/453）而 trap 没有——
配了端口的用户无法确认链路是否在工作。

**方案**：设置页 syslog 状态行旁并排 trap 状态（监听端口/最近收到时间/缓冲数/近 1h 去重后事件数）。

**验收**：交换机发一条测试 trap，状态行 10 秒内出现「最近收到」变化。

### 2.5 凭证清除

**现状**：`NetDevDeleteSecret` 零调用；设置页只能看「✓ 已设」（NetDevSection.tsx:247），
不能删除已存密码（只能覆盖）。

**方案**：设备/跳板/DB 源编辑表单加「清除已存凭证」按钮（确认对话框 + 落审计）。

**验收**：清除后设备卡凭证列回到「✗ 未设」，测试连接提示无凭证。

## §3 C2 引导层重建（P1，约 1.5 周）

### 3.1 结果归位：err banner → 结构化结果卡

**现状**：`runLocate` / `runExpected` / `runTriageAll` / `runWeakCredAll` 的**成功结果全部
`setErr` 写进红色错误横幅**（NetDevLayout.tsx:607/621/664/688），终端 Start（:1076）与
状态导出（审计页 :966 附近）同病。成功被错误样式展示、不可复制、无下一步跳转。

**方案**：新增中性「结果卡」组件（成功/警告两态，非 error 样式）承载全网动作回执：
- 定位：命中表（设备:接口）+ 覆盖率 + 「未覆盖≠不存在」警告保留；
- 期望状态：缺失设备 chips，点击跳设备页签；
- 体检/弱口令：汇总数字 + 「查看发现」按钮跳发现页签并自动过滤来源；
- `setErr` 保留给真实错误。

**验收**：四个动作的结果以结果卡呈现且均可一键跳转对应页签；回归——真实报错仍走红横幅。

### 3.2 ScenarioHub 扩容：6 → 14 张卡

**现状**：场景引导中心只有 6 卡（NetDevLayout.tsx:1417-1424），下表左列能力全部已接线却无场景入口：

| 新增卡 | 动作直达 |
|---|---|
| IP/MAC 定位 | 清单页签定位框聚焦（并把该输入框从角落提到卡内） |
| 主机体检 | 巡检家族菜单「主机体检」 |
| 弱口令核查 | 巡检家族菜单「弱口令」 |
| CVE 清单匹配 | 安全工作台 CVE 区（依赖 2.3） |
| 入侵排查向导 | 主区切「安全」+ 新建案例 |
| 变更-故障关联 | 日志工作台开关联源（时间窗可调，见 4.6） |
| 报告族 | 交接/周报/凭证盘点三按钮（现藏审计页 :959-962，保留原位双入口） |
| 容器/K8s 诊断 | 设置引导：无 kind 设备时卡片文案教配 kind |

卡片保持现构型（一句话 + 一个动作），主区双列网格改三列或加「更多」折叠。

**验收**：新用户不读文档，从场景引导 2 次点击内发起上表任一能力。

### 3.3 对话引导：建议 chips

**现状**：netdev 模式全部对话引导是一句 placeholder 例句（App.tsx:3161）。
后端 21 个 agent 工具的正确问法（netconf/snmp/locate/discover/assess…）全靠用户自己知道。

**方案**：composer 空态时在输入框上方出 4–6 条轮换建议 chips（点击即填入），
覆盖高频+低发现度能力的用户语言问法，如「扫一下 10.30.0.0/24 有哪些活主机」（discover）、
「用 NETCONF 拉一下 core-sw-1 的接口状态」（netconf）、「10.30.4.17 这个 IP 接在哪」（locate）、
「评估一下全网口令强度」（assess）。chips 数据放前端常量，随 locale 双语。

**验收**：英文/中文界面下均出现建议 chips；点击任一 chip 发送后 AI 走对应工具（人工抽查 6 条）。

### 3.4 断头路 signpost

- golden 无备份：设备卡 golden 区空态给「先立即备份」按钮（链 BackupHistory）；
- 日志面板 db 源为空：空态给「去设置添加数据库源」深链（对照 HealthPanel 轮询空态的既有模式）；
- 设置页设备表单：kind 选择器旁加一行说明「配成 docker/k8s/firewall 后设备卡会出现对应只读诊断动作」。

## §4 C3 面板能力补全（P2，约 2 周）

### 4.1 提案：驳回 + 列表治理（写路径完整性，本批最高优先）

**现状**：写路径人工闸门**只能放行不能否决**——无 reject/删除/筛选/分页；
dock 提案页签 `slice(0, 10)` 只显 10 条（NetDevLayout.tsx:1259）；
`ProposalCenter` 独立组件是死代码（ProposalCenter.tsx:87 无人挂载，仅 `ProposalActions` 被引用）。

**方案**：
- `ProposalActions` 增加「驳回」（draft/approved 态可驳，落审计，agent 下一轮可见被拒原因）与「删除」（仅 draft/已终结态）；
- 删除死代码 `ProposalCenter` 独立组件，dock 页签改为复用其列表逻辑：状态筛选 chips + 分页/「加载更多」，去掉 10 条硬顶。

**验收**：驳回一条提案后 agent 收到拒绝原因并停止推进；列表可按状态筛选且不再截断。

### 4.2 导出体系（横向）

**现状**：仅审计页有报告导出；日志、合并时间线、案例、健康快照均无导出。

**方案**：统一「导出」按钮（复用 sessionExport 的文件落盘通道）：
日志面板当前缓冲 → .txt/.log；日志工作台合并时间线 → .txt（含来源徽标文本化）；
案例详情 → Markdown（CaseBundle 已有，补「另存为文件」）；健康快照 → CSV。

**验收**：四类导出各一次真机验证文件内容与界面一致。

### 4.3 HealthPanel 深化

- 展示 `interfaces` 明细（数据在手只算计数，HealthPanel.tsx:73-74）：设备行展开 → 接口表（名/状态/最近变化）；
- sparkline 指标选择：可达性 / uptime / 掉线口数（`NetDevMetricHistory` 已有数据面）；
- 默认排序「异常置顶」+ 掉线口数筛选。

### 4.4 JobsPanel 自动化

- 30s 轮询（与父层 reload 同步）；「立即运行」后该行进入运行态直至历史出现新条目；
- 行内启停开关（调 SetNetDevSettings 改 enabled，不必跳设置页）。

### 4.5 SecWorkbench 修正

- 「并行主机体检」文案与实现对齐：改为真并行（Promise.all + 并发上限 4）；
- 设备范围选择器：>12 台时换可搜索多选（现为 slice(0,12)，SecWorkbench.tsx:204）；
- IOC note 可编辑、时间线引用卡可删除、案例可改名（三处小表单）。

### 4.6 LogWorkbench 补强

- 跨设备搜索的设备/作用域参数接真实选择器（现为写死空数组，LogWorkbench.tsx:177）；
- 关联时间窗可调（24h/7d/自定义，现为固定 `NetDevTimeline("", 24)` :144）。

### 4.7 AlertSetupWizard 补强

- 步骤校验（空 webhook 不能下一步）；预设规则集从 3 条扩到含 CPU/内存水位等 SNMP 指标项；
- 通知出口选项收录 SMTP（设置页已支持）。

### 4.8 LiveOpsPanel 兜底

- 手动刷新按钮；护栏拦截行可单条「知道了」收起（不清审计，仅 UI 归档）。

### 4.9 i18n 全量接入

**现状**：8 个面板文案全部硬编码中文（locales 仅有外壳 key），英文界面下仍中文。

**方案**：按编码模式面板既有流程补 `netdev.*` 双语键；本批与 4.1–4.8 合并提交，避免二次翻新。

### 4.10 快捷键最小集

`r` 刷新当前页签、`/` 聚焦各面板搜索框、`Esc` 层级退出（现有基础上补前两类）。

## §5 C4 后端能力接线（P2–P3，约 1 周）

### 5.1 发现按钮

`netdev_discover` 工具已注册（tools.go:540）、设置页已有发现模式/并发/白名单配置，
但 GUI 无触发入口。清单页签加「发现」按钮 → 弹窗输入 CIDR（默认取白名单第一项）→
调后端 DiscoverTCP（新增薄 App 方法或复用 agent 通道）→ 结果照常进「发现」待确认区。
**白名单校验必须在拨号前**（不变量 4）。

### 5.2 弱口令字典档

`NetDevWeakCredCheck` 的 tier 恒传 `"basic"`（NetDevLayout.tsx:682）、后端 `dict_path` 恒传 `""`
（netdev_app.go:909-912）。接线：巡检家族菜单加「强档（自定义字典）」；设置页高级区加字典文件路径
（本地路径，内容永不入导出）。

### 5.3 bot 命令闭环

现仅 `/netdev 发现` + `/netdev 详情` 两条只读（netdevcmds.go:69/85）。新增：
`/netdev ack <id>`（确认告警）与 `/netdev 提案 <批准|驳回> <id>`（复用既有 App 审批路径与群组策略校验）。
通知消息里附命令模板，让手机端告警可操作。

### 5.4 netconf 入口（轻）

设备卡协议含 netconf 的设备加 1–2 个只读快捷（get-running / get-interfaces，
走 `NetDevQuickExec` 同款展示区）；不做自由 RPC 输入框。

### 5.5 信任域消费（观察项，可延后）

`netdev_fleet`/`netdev_remote` 与 RemoteWorkHandler 完整实现但运维页零体现。
建议仅加只读公告板页签（成员/自证/暂停态）——写操作维持 CLI，UI 不做（与信任域 spec §16 未决问题一致）。
