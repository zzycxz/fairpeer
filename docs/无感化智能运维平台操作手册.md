## 前言

本手册覆盖平台日常使用的全部操作，按"一个场景一节"组织，可按需独立查阅。各节统一按五个部分编写：功能说明、适用角色、前置条件、操作步骤（含每步预期结果）、注意事项与常见问题。初次使用建议先通读第一、二节，再按岗位选读：运维工程师重点看三至九节，网安人员重点看九至十二节，文员看十五节，值守人员看十三、十四、十六节。

## 一、平台概述与界面总览

### 1.1 平台做什么

平台是一个部署在个人办公电脑上的智能运维助手：工程师用自然语言提出请求，平台自动识别要查的设备、生成检查计划、逐条执行只读命令、汇总结论并附证据。写操作（配置变更、封禁、提单）一律以"提案"形态出现，由人审批后才执行。所有对外动作全程留痕，可事后回放。

三条铁律贯穿全部操作，遇到任何疑问先回想这三条：

1. **读是默认**：诊断类操作只读，结构性保证，任何模式下不放开；
2. **写是例外**：写操作唯一路径是"AI 起草 → 人批准 → 先备份 → 执行 → 可回滚"；
3. **凭证不落地**：密码等敏感信息存加密存储，配置文件和对话记录里不出现明文。

### 1.2 界面总览

界面分四个区域，方位如下：

| 区域 | 位置 | 内容 |
|---|---|---|
| 标题栏 | 最上方 | 网络身份、项目切换器、诊断策略入口、紧急停止按钮 |
| 左栏 | 左侧 | 诊断会话列表、设备清单（按项目过滤）、堡垒链、巡检入口 |
| 中间主区 | 中央 | 诊断对话主循环、图表渲染、欢迎页示例 |
| 右栏 | 右侧 | 多页签：实况 / 日志 / 健康 / 设备 / 网络 / 拓扑 / 上下文 / 发现 / 变更 / 审计 / 历史 / 状态 |
| 底部状态栏 | 最下方 | 今日只读 / 写 / 变更三类计数（等宽数字） |

右栏常用页签速记：

- **实况**：每条命令、输出、护栏拦截的实时画面，含本轮命令预算条和设备登录通道占用情况；
- **发现**：诊断结论（含证据）按严重程度排队，同类合并；
- **变更**：提案的行内审批与执行状态；
- **审计**：全部操作的时间线记录，含拒绝与批准，附防篡改校验状态。

设置集中在「设置 → 运维」页：设备、跳板、分组、项目、护栏、读表、探测范围、巡检、审计、变更中心。

## 二、安装与首次启动

**功能说明**：完成平台部署，达到可接入设备的状态。

**前置条件**：一台办公电脑（Windows），具备局域网访问能力；如需本地模型，模型服务已就位。

**操作步骤**：

1. 双击安装包，按向导完成安装。平台为单安装包，无其他运行时依赖；
   - 预期：安装完成，桌面出现启动图标。
2. 首次启动进入主界面，右上角点「设置」；
   - 预期：打开设置面板，左侧为分类导航。
3. 进入「设置 → 运维」，此页承担后续全部配置；
   - 预期：看到设备、跳板、分组、项目、护栏等配置分区。
4. （可选）在「设置 → 模型」确认模型端点已配置（见第十七节本地模型接入）；
   - 预期：测试对话可正常应答。
5. 回到主界面，查看中间欢迎页的示例指令，了解可直接提问的类型；
   - 预期：欢迎页列出若干示例，如"查看设备清单""这台交换机接口状态怎么样"。
6. ★ 查看底部状态栏三类计数（只读/写/变更），当前应为 0 或历史累计值；
   - 预期：计数随操作增长，这是演示"全程留痕"的好画面。

**注意事项**：

- 安装包无需管理员权限亦可安装（依公司策略而定）；如被终端管控拦截，联系管理员加白；
- 首次启动后建议先做一次"冷启动验证"：设置→运维→护栏里确认结构性只读处于恒开状态（该项无开关，若界面异常请联系研发）。

## 三、接入第一台设备

**功能说明**：将一台服务器或网络设备纳入平台管理，建立可用连接。

**适用角色**：运维工程师。

**前置条件**：目标设备可经 SSH 访问；已申请到该设备的登录账号（权限与人工运维相同即可，无需特权）；如经跳板机，跳板账号已就绪。

**操作步骤**：

1. 「设置 → 运维 → 设备」，点「添加设备」；
   - 预期：弹出设备表单。
2. 填写设备名称、地址、厂商/类型（数通设备选厂商，服务器选 Linux/Windows）、所属分组；
   - 预期：字段校验通过。分组决定后续护栏策略（只读/变更/双确认）。
3. 凭证栏填写**环境变量名**而非明文密码（密码本身存放在系统加密存储）；
   - 预期：配置文件中只出现变量名；明文不会出现在任何导出内容里。
4. 跳板机环境先在「设置 → 运维 → 跳板」配置堡垒链，再在设备表单选择对应链路；
   - 预期：连接时按链路逐跳登录，链路状态显示在左栏「堡垒链」。
5. ★ 点「测试连接」；
   - 预期：首次连接弹出设备指纹确认框（防中间人），核对指纹后点「确认」。此后指纹若变化会在连接时告警。
6. 连接成功后左栏设备清单出现该设备；
   - 预期：中间欢迎页的示例指令变为可用状态，设备卡片可点开。
7. 批量接入：支持从现有 SSH 配置文件导入，或逐台添加；
   - 预期：导入后设备清单批量出现，逐台「测试连接」验证。

**注意事项**：

- 一台设备的接入耗时应在一两分钟内（录地址、选厂商、测试连接三步）；
- 设备分组建议按"核心/汇聚/接入"或"生产/测试"划分，护栏策略按组下发，后续管理事半功倍；
- 删除设备不影响其历史备份与审计记录。

**常见问题**：

- *测试连接超时*：先确认本机可直接 SSH 该设备；经跳板的检查跳板链顺序与账号；
- *指纹告警*：若近期确有设备更换/升级，核实后重新确认；无缘由的指纹变化按安全事件对待。

## 四、日常诊断（对话主循环）

**功能说明**：以自然语言发起诊断，平台自动采集、汇总并给出带证据的结论。这是使用频率最高的入口。

**适用角色**：全部技术岗。

**前置条件**：至少一台设备已接入；建议已配置项目与分组（用于范围裁剪）。

**操作步骤**：

1. 在中间对话框用一句话描述问题，例如"核心业务访问慢，帮我查一下"；
   - 预期：平台先回复它理解的意图与计划检查的设备清单（清单受项目/分组过滤，越界设备不会出现）。
2. 确认计划后平台逐条执行只读命令；
   - 预期：每条命令与回显摘要出现在对话流中；被安全检查拦截的命令会显示明确拒绝原因。
3. ★ 同步打开右栏「实况」页签；
   - 预期：实时看到命令、原始输出、拦截记录、本轮命令预算条、设备登录通道占用。
4. 平台汇总关联推理，输出结论；
   - 预期：结论附带证据链——哪台设备、什么时间、执行了什么命令、看到了什么；涉及路径/邻居的内容渲染为拓扑图。
5. 右栏「发现」页卡查看排队结果；
   - 预期：结论按严重程度排列，同类合并（如"接口 down ×17"一条，展开看明细）。
6. 点开任一结论核对证据原文；
   - 预期：证据面板显示脱敏后的原始输出（密码等字段已指纹化）。

**注意事项**：

- 描述问题时带上范围信息（哪台设备、哪个业务、大概时间），平台裁剪更快；
- 每轮对话有命令预算（默认不限，可在护栏中设置），预算用尽会提示，防止误伤设备；
- 诊断永不修改设备：即使指令里说"帮我改一下"，写意图也会被转入提案流程（见第八节）。

**常见问题**：

- *平台说某台设备不在范围内*：检查「设置 → 运维 → 护栏 → allowed_groups」，以及当前项目是否包含该设备；
- *命令被拒绝但确实是只读命令*：见第五节"教读表"。

## 五、教平台认识新命令（读表授权）

**功能说明**：平台内置了各厂商常用只读命令白名单。遇到白名单外的命令，由人一次性授权，之后平台可继续使用。

**适用角色**：运维工程师（仅人工可操作，AI 无权自授）。

**操作步骤**：

1. 对话中请求一条平台不认识的只读命令（如某厂商新增的查询命令）；
   - 预期：平台拒绝并说明"该命令不在读表内"，拒绝记录进审计。
2. 打开左栏设备清单，点目标设备进入设备卡；
   - 预期：设备卡展开，显示快捷命令、抓配置、AI 变更等入口。
3. ★ 在拒绝提示旁点「允许此命令」；
   - 预期：命令写入该设备的扩展读表，立即生效（无需重启）。
4. 回到对话框重新发起请求；
   - 预期：该命令正常执行，回显照常脱敏后进入上下文。

**注意事项**：

- 授权是**设备级**的：给 A 设备授的命令不影响 B 设备；
- 授权记录进审计；误授权可在「设置 → 运维 → 读表」中移除；
- 多行命令、带管道拼接的命令不会进入读表——这是防夹带的设计，属正常拒绝。

## 六、定时巡检与主机分诊

**功能说明**：对设备做周期性只读体检，结果自动落入发现页卡；服务器侧提供主机分诊、安全基线、弱口令评估入口。

**适用角色**：运维工程师、网安人员。

**操作步骤**：

1. 单次巡检：左栏点「立即巡检」；
   - 预期：平台对清单内设备执行只读检查电池（接口、告警、资源等），结果汇总入「发现」。
2. 周期巡检：「设置 → 运维 → 巡检」配置巡检间隔；
   - 预期：到点自动执行，与"立即巡检"同一套只读检查。
3. 服务器侧扩展检查：左栏巡检入口右侧「▾」溢出菜单；
   - 预期：菜单列出"主机分诊 / 安全基线核查 / 弱口令评估"。主机分诊需要登录凭据，基线与弱口令按需选择执行。
4. ★ 巡检完成后在「发现」页卡查看；
   - 预期：每条异常附证据与建议，可一键插入变更指令。

**注意事项**：

- 巡检是纯只读操作，可在业务时段执行；
- 大批量设备的巡检任务在后台执行，中断可从断点续跑。

## 七、配置备份与版本对比

**功能说明**：自动周期备份设备运行配置，形成不可变版本库，支持任意两版本对比与恢复提案起草。

**适用角色**：运维工程师。

**操作步骤**：

1. 自动备份：「设置 → 运维」配置备份间隔（backup_interval）；
   - 预期：平台按周期对全部支持的设备抓取运行配置并存为版本。
2. 手动备份：设备卡点「抓配置」；
   - 预期：立即生成一个新版本，出现在备份列表顶部。
3. ★ 版本对比：设备卡「备份」列表任选两个版本点「对比」；
   - 预期：输出差异视图（敏感字段已脱敏）——"这次到底改了什么"一眼可见。
4. 恢复起草：选定目标版本点「起草恢复提案」；
   - 预期：AI 对比当前配置与目标版本差异，起草恢复步骤（每步附回滚命令），转入变更审批流程（第八节）。

**注意事项**：

- 备份版本不可变、不可删改，是变更回退的最终依据；
- 并非所有设备类型都支持配置抓取，当前覆盖主流厂商数通设备（清单见产品说明），不支持的平台会明确提示而不是静默跳过。

## 八、变更提案与审批

**功能说明**：所有写操作（配置变更、批量调整）的唯一通道：AI 起草提案 → 人行内审批 → 先备份 → 执行 → 验证 → 可回滚。

**适用角色**：运维工程师起草/执行，按组策略确定审批人。

**前置条件**：目标设备所在分组策略允许变更；如配置了变更窗口，当前时间须在窗口内。

**操作步骤**：

1. 对话中说"帮我把 xx 接口的描述改为 xxx"；
   - 预期：AI 先执行只读命令确认现状，然后生成结构化提案。
2. ★ 右栏「变更」页签出现待审提案；
   - 预期：提案逐步列出：每步命令、影响说明、对应的回滚命令；受变更窗口与组策略约束的会标注。
3. 逐行核对步骤，点行内「批准」；
   - 预期：提案进入执行队列。可整份批准或驳回。
4. 执行阶段；
   - 预期：平台自动先对目标设备做配置备份，然后逐台执行、逐台验证；每步结果实时显示。
5. 异常处理；
   - 预期：任一台执行失败即自动冻结后续设备，界面提示失败点与已执行步骤，可按回滚计划回退（回滚同样先备份）。
6. 复盘；
   - 预期：起草、批准、备份、执行、验证、回滚全部动作在「审计」页签可查。

**注意事项**：

- 割接类多步骤操作使用"割接模式"：按 runbook 逐段执行，段间验证门，回退决策点自动暂停等人决定；
- 执行前平台会检查目标设备上是否有其他在线人员，避免同时操作；
- AI 在任何模式下都不能绕过审批自行执行写操作。

## 九、安全基线核查

**功能说明**：读取设备运行配置，按内置规则检查常见安全隐患（明文管理服务、弱版本协议、密码明文存储、日志未外发等）。

**适用角色**：网安人员。

**操作步骤**：

1. 右栏「发现」页卡点「安全基线核查」，或对话中说"做一轮基线核查"；
   - 预期：平台逐台读取运行配置（密封只读），按规则集匹配。
2. ★ 查看结果；
   - 预期：命中项落入发现列表，每条含：规则名、严重级别、脱敏证据、修复建议。
3. 修复；
   - 预期：修复建议可一键"插入变更指令"，转第八节提案流程，不自动执行。

**注意事项**：

- 规则集内置且持续更新，无需自行维护规则文件；
- 基线核查同样适用于周期巡检场景（第六节）。

## 十、受控弱口令评估

**功能说明**：在授权信封有效期内，对设备做有硬顶次数限制的弱口令核查。用于安全评估，日常默认关闭。

**适用角色**：网安人员（需评估信封）。

**操作步骤**：

1. 管理员配置评估信封（含编号、有效期、批准人）；
   - 预期：信封生效后平台注册评估能力；信封缺失或过期一律拒绝并落审计。
2. 选择设备发起弱口令核查（基础档或字典档）；
   - 预期：基础档每目标尝试次数硬顶 3 次，字典档硬顶 10 次，凭据来自本地小字典，绝不在线爆破。
3. ★ 查看结果；
   - 预期：命中项落入发现列表，附证据；次数用尽自动停止。

**注意事项**：

- 评估能力随信封到期自动失效，需重新授权；
- 该功能定位是自查自纠，不提供对外攻击能力。

## 十一、漏洞核查（蓝队核查）

**功能说明**：对服务器/设备做漏洞存在性核查：采集软件指纹 → 匹配情报 → 只读验证 → 立案存证，输出修复建议。

**适用角色**：网安人员、运维工程师。

**前置条件**：如需情报匹配，先导入 CVE 情报（平台不分发情报，需自备）。

**操作步骤**：

1. 导入情报：「设置 → 运维 → 安全工作台」粘贴导入公开 CVE 情报；
   - 预期：情报入库，后续匹配基于该库。
2. 对话中说"对这批服务器做一轮漏洞核查"；
   - 预期：平台逐台读取软件包清单（Linux 读包管理器，Windows 读补丁级与已装软件；网络设备读版本信息），多台同类设备自动并行。
3. 匹配与验证；
   - 预期：设备×情报粗命中后，平台以版本区间比对做只读验证；无法确证的标注"待人工核对"，不凭模型记忆断言。
4. ★ 查看结果；
   - 预期：确认命中逐条落入「发现」（来源标记漏洞核查），附命令输出证据与修复建议。
5. 修复闭环；
   - 预期：修复建议可插入变更指令，整改走提案审批。

**注意事项**：

- 平台不做利用性验证（不验证"能不能打穿"），只验证"有没有"；
- 主动扫描类动作受评估信封约束，核查流程不开启不绕过。

## 十二、日志审计

**功能说明**：多机日志统一采集、合并时间线、跨设备检索，结果可导出报告。

**适用角色**：项目经理、网安人员、运维工程师。

**操作步骤**：

## 十三、浏览器技能：录制与一键运行

**功能说明**：对任意 Web 系统（态势感知、智算平台、MOMA 等）录制操作技能，之后一键确定性回放。这是对既有 Web 系统"零改造嵌入"的核心能力。

**适用角色**：全部岗位（录制需熟悉目标系统的人，运行无门槛）。

**前置条件**：目标系统可用浏览器正常访问（含登录、验证码流程）。

**操作步骤**：

1. 进入「浏览器」工作台；
   - 预期：主区打开受控浏览器，右侧驾驶舱出现三个页签：「交互」「录制」「技能」。
2. ★ 「录制」页签点开始，在浏览器里手动完整走一遍目标操作（**含登录与验证码**）；
   - 预期：操作轨迹被实时记录。
3. 停止录制；
   - 预期：轨迹被自动归纳成步骤表草稿。
4. 人工校对步骤表：删误、合并、把具体值（IP、日期、单号）改为可替换变量；
   - 预期：步骤表保存为技能（命名如"态势巡检"），进入技能库。
5. 一键运行：「技能」页签选技能、填变量值、点「运行」；
   - 预期：受控浏览器按步骤表自动执行，步骤面板逐条点亮；执行路径与录制一致（确定性回放）。
6. 写操作确认；
   - 预期：涉及封禁、提单、提交等写操作时，自动停在确认页，由人点最后一击。
7. 结果处理；
   - 预期：运行结果落入结果页卡，可导出报告或转发现列表。

**注意事项**：

- 目标系统改版导致步骤走不通时，技能会**停在原地报错**，不会乱点；按报错步骤重新录制该段即可；
- 技能可复制：换个环境只需修改变量（地址、账号引用），适合跨机房复用；
- 轮询类技能（如告警轮询）可配置定时执行，见第十四节。

## 十四、告警轮询与晨报

**功能说明**：对告警类页面技能开启轮询，自动完成危险评判；每日晨报定时推送夜间巡检与告警汇总。

**适用角色**：值守人员、网安人员。

**操作步骤**：

2. 「设置 → 运维」配置推送时间与通知出口（IM / 邮件）；
   - 预期：配置保存后按计划触发。
3. ★ 高价值告警实时推送；

4. ★ 晨报；
   - 预期：每日定时收到晨报，含夜间巡检结果、告警汇总与待办交接内容。

**注意事项**：

- 轮询频率建议贴合目标系统刷新频率，无需过密；
- 通知出口不可用时平台会本地留存结果，出口恢复后可在结果页卡补看。

## 十六、移动端 LinkPeer

**功能说明**：手机经局域网点对点直连办公电脑，远程查看会话、发送指令、处理审批。全程端到端加密，不经外部服务器。

**适用角色**：值守人员、运维工程师。

**操作步骤**：

1. 手机安装 LinkPeer，与办公电脑接入同一局域网；
2. ★ 平台发起配对，手机输入配对码完成绑定；
   - 预期：绑定后设备记录在案，后续连接免重复配对。
3. 连接后手机端查看当前会话与通知；
   - 预期：手机可阅读对话、查看发现列表、收到审批提醒。
4. 处理事务；
   - 预期：简单指令可直接在手机端发起；审批可在手机端完成。
5. 断开；
   - 预期：随时断开不影响桌面端会话，重连即可恢复。

**注意事项**：

- 配对码一次一用，勿外传；
- 跨网段/ VPN 环境下以实际连通性为准，平台不提供外网中转（安全边界如此设计）。

## 十七、本地模型接入

**功能说明**：将模型切换为本地部署的推理服务（OpenAI 兼容接口），实现"模型在局域网内、数据不出机房"。

**操作步骤**：

1. 「设置 → 模型」进入模型配置（对应配置文件的模型段落）；
2. 填写本地推理服务地址与模型名（OpenAI 兼容格式）；
3. 将运维场景使用的模型端点切换为本地端点，保存；
   - 预期：后续对话由本地模型服务；界面无感切换。
4. 配置备用端点（可选）；
   - 预期：主端点不可用时自动切换备用，全部端点不可用则任务挂起提示，不空转。

**注意事项**：

- 本地模型的吞吐决定响应速度，慢是正常现象，安全优先；
- 模型端点切换记录不进入审计（不涉及设备操作），但对话记录的存储位置不变（本地加密）。

**功能说明**：应急断连与操作回溯。

**操作步骤**：

   - 预期：审计记录可导出，供等保检查与内部审计使用。

## 附录 B：常见问题（FAQ）

1. **命令被拒绝，但我觉得是安全的** → 第五节教读表，设备卡上一键授权；多行/拼接命令属设计性拒绝。
2. **AI 看不到某台设备** → 检查项目切换器与分组范围（allowed_groups）；范围裁剪发生在进模型之前。
3. **提案执行到一半失败** → 平台已自动冻结后续；按界面提示回退已执行步骤（回退同样先备份），失败点可导出给研发。
4. **技能跑到某步停住报错** → 目标页面大概率改版；按报错步骤重新录制该段。技能停在原地是保护行为。
5. **晨报没收到** → 检查推送时间与通知出口配置；结果页卡可补看本地留存。
6. **模型无响应** → 本地端点服务状态；备用端点会自动接管，全部不可用则挂起等待，不会乱试。
7. **Excel 比对大文件很慢** → 先按时间/关键字缩小范围；超大文件建议分片。
8. **拓扑图和实际不符** → 拓扑默认是本地推断视图（零拨号），点「LLDP 实测校准」后以实测为准，两种来源有徽标区分。
9. **紧急停止后设备登不上** → 紧急停止释放了登录通道，稍等平台重连或手动点设备卡重连。
10. **换电脑怎么迁移** → 配置与加密存储整体迁移（导出→导入），设备、技能、知识库随迁。
