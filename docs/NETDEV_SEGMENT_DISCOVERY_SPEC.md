# 入口 IP → 网段发现流程（SEGMENT_DISCOVERY_SPEC v1）

场景：评估/排查时拿到一个入口 IP，需要快速收敛出它所在的网段及邻接网段。
问题：私网空间巨大（10/8 = 1677 万地址），无脑穷举永远跑不完，也永远不该跑。

## 0. 核心理念

1. **信息优先，探测兜底**：每个网络环境自带地图——路由表、ARP/MAC 表、DHCP 租约、
   DNS、平台存量清单。这些是"别人已经扫好的结果"，读表代价 = 一条只读命令。
   盲扫的本质错误是把发现外包给带宽；本流程里，**发包只用于验证假设**。
2. **假设驱动，小步验证**：没有假设不发包。每一次探测都必须对应一个具体假设
   （"网关是 .1"、"这是 /24"），配一个最小验证动作和一个通过标准。
3. **证据半径**：探测范围不得超过当前证据支持的半径。扩半径（新网段）必须由
   新证据（路由条目、ARP 表、清单命中）触发，然后回到验证循环。
4. **人的嗅觉编码化**：老运维的直觉写成显式启发式（§4）——看到 X → 想到 Y →
   用 Z 验证。推断可以发散，探测永远收敛。

## 0.5 总图（三轮收敛后的最终顺序）

```
【0】定标：入口IP + 范围口径（scopes）
  │
  ▼
【1】榨情报（零发包·只读密封·按权威度排序）
  ① 平台存量清单 —— 免费，先查同段命中
  ② 网关读表 —— 路由表 → ARP → MAC
  ③ 主机本体 —— 掩码 / 静态路由 / 本地ARP
  ④ 反查 —— PTR / 证书SAN / 命名规律
  │  每条信息立即转成假设
  ▼
【2】假设队列（段候选 × 置信度 × 证据链）◄────────────┐
  │ 取最高置信                                       │
  ▼                                                 │
【3】最小验证（信封内·最小发包）                        │ 新线索
  网关单点 → TTL → 采样 4-6 点 → 判定                  │ 回灌
  ├─ 不通过 → 回【1】换证据（禁止加大探测）              │ =唯一合法
  └─ 通过                                            │  扩段路径
  ▼                                                 │ (需人工确认)
【4】段地图入库 + 嗅觉再排序 ──────────────────────────┤
  段 × 角色 × 置信度；生产段 > 基础设施 > 办公段          │
  │                                                 │
  ▼                                                 │
【5】停止判定：证据耗尽 / 预算用尽 / 覆盖达标             │
  ├─ 未停 → 回【2】取下一假设 ──────────────────────────┤
  └─ 停                                              ▼
【6】交接：人工确认证据链 → 段地图交付扫描排程 / 蓝队核查队列
```

读/探分属两个权限世界：【1】走只读密封（display/show 前缀，无需信封），
【3】的发包必须信封 + scopes——顺序保证所有"读"榨干后才进"探"。
每轮循环必须二选一产出：新段入库，或一个假设的死亡判决；禁止空转。

## 1. Phase A：零发包情报（只读密封下即可跑，不需要评估信封）

### A1 平台在管设备读表（产品杀手锏，优先级最高）

| 读什么 | 命令（按厂商） | 等效于 | 产出 |
|---|---|---|---|
| ARP 表 | `display arp` / `show ip arp` | 整段活性扫描（零流量） | IP↔MAC 活体台账 |
| MAC 表 | `display mac-address` / `show mac address-table` | L2 全景 | 端口规模、设备密度 |
| 路由表 | `display ip routing-table` / `show ip route` | 相邻网段清单 | Direct/connected 条目 = 直连段全集 |
| 接口 IP | `display ip interface brief` / `show ip interface brief` | 段边界 | 本机在每个段的身份 |
| DHCP | `display dhcp server statistics` 等 | 地址池范围 | 办公/终端段边界 |

一张路由表常常直接给出全部邻接网段；一张 ARP 表就是该网段的活主机清单。
**"快速找到地址段"的正解不是搜，是读表。** 注意读表顺序：先路由表（网段全集）
→ 再对目标段读 ARP（活体清单）→ MAC 表补充端口规模。

### A2 入口主机本体（若已持访问权，走 netdev_exec）

- `ip addr` / `ipconfig`：IP + 掩码 → 候选 CIDR（掩码是第一证据，/24 是默认假设）
- `ip route` / `route print`：网关 + 静态路由 → 隐藏的邻接段（静态路由指向的段
  往往是核心资产段）
- `arp -n` / `arp -a`：本机见过的邻居 = 活主机证据，零发包
- `/etc/resolv.conf`、域名后缀、`hostname`：命名规律的起点

### A3 平台存量数据（发任何包之前先查）

- `netdev_devices` 清单：其他设备的 address 就是段内活体证据——清单里已有
  10.34.12.7，入口 IP 是 10.34.12.5，则 10.34.12.0/24 立即成为高置信候选。
- `netdev_topology`（CDP/LLDP 邻接）：段间关系。
- 存量配置：ACL、静态路由、DHCP 池配置都是段布局的书面证据。

## 2. Phase B：纯黑盒推断（只有 IP、还没登录任何东西时）

1. **候选段生成**：掩码未知 → /24 默认假设（企业最常见管理边界）。
2. **单点验证**：ping 网关候选（.1 → .254 → .249 次序）→ TTL 读数免费送拓扑：
   64=Linux 直连本段，63=隔一跳，128=Windows，127=路径上有 NAT/L3 设备。
   TCP 连已知端口读 TTL 同理。
3. **小样本采样**：候选 /24 抽 4-6 点（.1 .2 .100 .254 + 随机 2 个）→ ≥2 活接受；
   0 活回退（换边界或回 Phase A）。netprobe 执行（信封内），限速。
4. **反向情报**：PTR 批查（/24 = 254 次 DNS 查询，安静）；服务 banner / TLS 证书
   SAN 抓 hostname → 域名 → 命名规律；traceroute 定上游网关。
5. **IPv6 特例**：`ping -6 ff02::1` 一次组播全体应答——v6 段发现反而最容易，
   别套用 v4 思路。

## 3. Phase C：每步的快速检验机制（假设-验证闭环）

| 步骤 | 假设 | 最小验证 | 通过标准 | 不通过回退 |
|---|---|---|---|---|
| 段候选 | 入口 IP ∈ X.X.X.0/24 | 采样 4-6 点 | ≥2 活 | 缩到 /26 或回 A 找掩码证据 |
| 网关 | .1 是网关 | ping + 本机 ARP | ARP 出现 MAC | 依次试 .254/.249/.3 |
| 段规模 | 单 /24 连续段 | ARP 表 IP 分布 | max-min < 256 且聚集 | 按 ARP 聚类拆段 |
| 命名规律 | 3 台同模式主机名 | 预测第 4 台并验证 | 命中 | 规律作废，只信实测 |
| 邻接段 | 路由表 Direct 条目可探 | 该段网关单点探活 | 活 | 仅记录，不下扫 |

原则：**任何扩半径动作之前，必须有一行"通过"的检验记录**；不通过就回到信息面，
绝不硬扫。所有假设与验证结果进 netdev_finding（评估记录），扩段决策点把证据链
交给用户确认——真人确认点是"人的嗅觉"的第二层。

## 4. 真人嗅觉启发式（编码进流程的直觉）

- 网关位置：.1 / .254 常规；HSRP/VRRP 组在 .1-.4；VIP/负载均衡 .253-.254。
- 地址聚集：.2-.19 密集 = 基础设施固定区；.20-.250 连续密集 = DHCP 池 =
  办公/终端段（价值密度低，跳过）；稀疏分布 = 生产段（固定 IP，价值高）。
- MAC OUI：网络厂商（Huawei/Cisco/H3C）出现在终端段 → 交换机/AP 在此段；
  服务器厂商聚集 = 计算段；打印机 OUI 密度 = 办公段。
- 主机名模式（bj3-web-01 = 地点-职能-序号）：从 1-2 台外推整段职能，
  预测下一台验证；命名规律还能跨段外推——**推断发散，探测收敛**。
- 段号编码：若第三八位编码机房/楼层（10.34.[12].0/24），从一个 /24 可推断
  整个站点布局——只用于指导优先级，不用于扩大扫描。
- 空段 ≠ 无段：可能是 VRF 预留/备用段，标记"证据不足"即止，不反复扫。
- 反常即情报：同一 /24 出现两种 TTL 分布 → 段内有 L3 设备或 NAT；
  ARP 中一个 IP 对多个 MAC → VIP/HA；MAC 表一个端口挂大量 MAC → 下联接入交换机。

## 5. 约束与平台映射

- **硬门控（已实现，不动）**：scopes 白名单永不可关；nmap 单次 ≤ 4096 主机；
  netprobe /16 级按 job 预算；全部信封后置（`AssessmentActive`）。
- **流程纪律（本文新增）**：证据半径。A 类私网整扫不是"慢"，是方向错误——
  10/8 整扫 = 1677 万地址，读一张路由表 = 1 条命令。
- **密封分工**：Phase A 全部走只读密封（display/show 前缀即 read，已验证
  分类器放行）；Phase B 的任何发包（采样、探活）必须信封 + scopes。
- **产出物**：每阶段落 netdev_finding；最终产出"段地图"——段清单 × 证据来源
  × 置信度 × 角色（生产/办公/基础设施），作为后续扫描/核查的排程输入。

## 6. 与现有编排的关系

- `netdev_nmap` / `netdev_netprobe`（信封内）：Phase B 的执行器，输入应收窄为
  本流程产出的"已验证段"，而不是用户手输的裸 CIDR。
- `netdev_topology` / `netdev_devices`：Phase A3 的数据源。
- 蓝队 vulnscan playbook：本流程的"段地图"决定其核查队列顺序（边界 > DMZ >
  关键角色 > 内网），两流共享"信息优先"纪律。
