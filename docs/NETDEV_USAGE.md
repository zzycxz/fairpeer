# 运维能力使用逻辑（Usage Map）

视角是"怎么用"：一个命令/按钮从哪进、经过什么闸门、结果落在哪。
规格细节见 `NETDEV_SPEC.md`；求助入口见 `NETDEV_HELP.md`。

---

## 一、总原则（一切能力的边界）

**读是默认，写按锁分级，攻是限时。**

- 读：结构只读密封——分类器表驱动，模型无法自我放开；不确定 = 拒绝。
- 写：**两把锁取严**（`NETDEV_WRITE_AUTHZ_SPEC.md` v1，随 P1 落地；落地前写仍唯一走变更）。
  锁 1 = 对话框模式（变更询问/自动编辑/完全访问），会话姿态，**只能收紧不能放宽**；
  锁 2 = 设备写档：`sealed`=提案（生产默认）/ `confirm`=逐条审批直写 / `auto`=直连
  +自动快照（实验/靶场）。任何一把锁单独打开都不足以导致写；硬底线（危险命令、
  恢复提案化等）任何档位都不可解锁。
- 攻（安全评估）：engagement 编号+有效期，到期自动失效。
- 凭证：TOML 只存环境变量名，值在加密存储；审计永不落原文；输出进上下文前先脱敏并提示条数。

## 二、八条主流程

### A. 首次接入（从零到能用）
设置 → 运维：录入设备（或 ~/.ssh/config 导入）→ 填地址/厂商/分组/凭证环境变量 →
**选写档**（WRITE_AUTHZ P1 起为必填项，sealed 预选；详见 H 节）→
「测试连接」（首次弹主机密钥指纹，确认即 TOFU 信任）→（可选）建项目、配护栏 →
回到页面：左栏出现设备，中间欢迎页给示例。发现中心「待确认区」转正走同一锁步骤。

### B. 日常诊断（主循环）
用户在对话框描述故障 → agent：
1. `netdev_devices` 看清单（受 allowed_groups 作用域过滤——模型的世界先被裁剪）
2. `netdev_exec` 逐条只读命令（display/show/ping/tracert/netconf get）
   闸门顺序：**多行拒绝 → 组作用域 → 每轮预算 → 分类器**（全部过了才拨设备）
3. 输出脱敏后进入上下文（敏感字段计数提示）
4. 关联推理 → mermaid 图（邻居/路径/流程）→ `netdev_finding` 落结论（必带证据）

**遇到未知命令**：拒绝并说明 → 用户在设备卡点「允许此命令」一键教读表
（[netdev.extra_read]，立即生效；只有用户能教）→ agent 下次即可用。

### C. 配置变更（写路径）
入口两个：拓扑图点节点 → 设备卡「AI 配置变更…」；或对话直接说。
- **sealed 设备（默认，生产）**：agent 先只读确认现状 → `netdev_propose` 起草
  （每步必带回滚命令，受变更窗口/组策略约束）→ 右栏「变更」tab **行内** 批准 →
  执行（逐台先备份）→ 部分失败即冻结 → 可按回滚计划回退。全程 agent 无执行权。
- **confirm / auto 设备（WRITE_AUTHZ P1 起）**：写命令走直连通道——confirm 档
  每条弹审批卡；auto 档直连。每条写都自动三明治：**改前抓配置快照 → 执行 →
  改后再抓 → 自动 diff 告诉你实际变了哪几行**（全部落备份库与审计）。
  对话框切到"变更询问"时 auto 档也逐条弹卡（两把锁取严，见 H 节）。

### D. 拓扑（本地优先）
进「拓扑」tab 即见 **IP 规划推断视图**：纯本地计算（分组→命名惯例→网段排序推
层级），零拨号零 AI，绝不编造连线。点「LLDP 实测校准」才逐台读邻居表补真实链路
（徽标区分两种来源，不静默混合）。点纳管节点 → 设备卡；未纳管邻居 → 录入引导。

### E. 周期任务与安全姿态
- 巡检：左栏「立即巡检」单击直跑只读电池 → Finding；主机分诊/基线/弱口令
  在其右侧 ▾ 溢出菜单（有登录或字典依赖，需显式选择）。inspection_interval 定时同只读电池。
- 安全基线：「发现」tab「安全基线核查」或 agent `netdev_baseline` →
  密封读 running-config → 本地规则（Telnet/SNMPv1v2c/明文密码/SSHv1/NTP/Syslog）
  → 命中入发现（带脱敏证据+修复建议，修复走变更）。
- 评估模式（攻，限时）：`[netdev.assessment]` 信封（engagement_id/expires/
  approver）有效时，agent 可用 `netdev_assess` 做弱口令核查——basic 档 ≤3 次、
  dictionary 档 ≤10 次硬顶（凭据来自本地小字典，绝不在线爆破）；信封缺失或
  过期一律拒绝并落审计。设备卡的同款入口走同一预算。

### F. 应急
标题栏「⏹ 紧急停止」：断开全部连接（释放 VTY），审计记录；Manager 随即可重连。

### G. 蓝队漏洞核查（对话驱动，结果落「蓝队核查」页卡）
对话框说"做一轮蓝队漏洞核查"（或右侧 dock「蓝队核查」页卡点「发起核查」插示例指令）→
agent 整任务委托 `netdev-seccheck-auto` 子代理（过程在操作实况可见，回传摘要，证据随立案落库）：
1. **指纹发现**（只读）：服务器读包清单与版本（`dpkg -l`/`rpm -qa`/`pip list`/
   `java -version`；Windows 用 `Get-HotFix` 补丁级与注册表已装软件），网络设备读
   `display version`/SNMP 版本；多台同类走 `netdev_fanout`。
2. **候选**：`netdev_cve_match`（已导入 CVE feed 时给出 设备×CVE 粗命中）+ 模型自身
   知识（标注"须验证"——知识有截止时间，绝不凭记忆断言无漏洞）。
3. **只读验证**：版本区间比对为主；定不了 → info 级"待人工核对"，不升级结论。
4. **立案**：确认命中逐条 `netdev_finding`（source=vulnscan，必带命令输出证据）；
   保存即推送到「蓝队核查」页卡（含 CVE 扫查 cve:* 来源），可建案例/跳发现/插
   修复变更指令。
红线：不做利用性验证；主动扫描（nmap/netprobe）须评估信封，核查不开不绕；
feed 用户自备（安全工作台 → CVE 粘贴导入，产品不分发）。

### H. 写档与备份（锁管理；`NETDEV_WRITE_AUTHZ_SPEC.md` v1，随 P1/P2 落地）

**给设备定锁（接入时必做）**：每台设备/工作区在接入时必须选写档，默认 sealed。
三层挂载：全局默认 → 组/工作区默认 → 设备覆盖（**只许收紧**：auto 组里的设备
可单独降回 sealed，反向不行）。设备卡与工作区头部常驻锁徽标：
🔒 sealed（提案）/ 🔐 confirm（逐条审批）/ ⚡ auto（直连+快照）。

**放宽要过告警确认**：把锁从 sealed 改宽（→confirm/→auto）或 confirm→auto 时，
弹出**独立告警卡**：写明后果（"设备 sw1 将允许 AI 直接执行写命令"），auto 档
需要**输入设备名**确认，确认记录进审计链。每次都弹、没有"不再提示"。
**手改 TOML 绕不过**：配置加载时发现未经确认的放宽，该设备按只读降级加载并在
界面告警——配置文件只是申请书，生效必须过人的确认。
**AI 永远开不了锁**：agent 工具面没有改写档的工具——锁是给人的。

**备份与回退在哪看**：每条直写的改前/改后快照、每次变更执行的备份、定时自动快照
（`[netdev.backup] interval`，默认每日）统一进**备份库**——设备卡「备份版本」
列时间线，任意两版可 diff、与现网可比对 drift（P2 起 drift 差异自动立案到发现中心，
持续回答"谁改了什么"）。可选开启 git 镜像（`git_mirror`）：备份目录变成一个
git 仓库，`git log -p` 直接看每台设备的配置演进史。
**每一步都可回退**：所有写操作（含回退本身）记入**操作台账**——时间线上每步
带 diff 与「回退此步」按钮（按设备写档走通道：auto 直连 / confirm 弹卡 /
sealed 提案），整会话可逆序回退；时间线任选版本的时间点恢复仍走提案。

## 三、护栏开关一览（设置 → 运维 → 护栏）

| 开关 | 默认 | 作用层级 |
|---|---|---|
| 结构性只读 | 恒开（无开关） | 每条命令（分类器；写类按写档放行，危险类恒拒） |
| 设备写档（锁 2） | sealed | 每台设备（组默认+收紧覆盖；放宽须告警确认） |
| 设备组策略 | 按组 | 提案管道（只读/变更/双确认）；与写档正交 |
| confirm_each_command | 关 | 每条工具调用弹审批卡（压过全自动模式） |
| turn_command_budget | 0=不限 | 每次提问（提交即重置） |
| turn_write_budget | 10（P1） | 每次提问的直写条数（独立于读预算） |
| allowed_groups | 空=全部 | 每次 AI 询问（清单+执行双过滤） |
| 备份 git 镜像 | 关（P2） | 备份库之外的审计层 |
| 脱敏/审计/预算提醒 | 恒开 | 回包透明度 |

## 四、界面 ↔ 能力对照

| 界面位置 | 承载能力 |
|---|---|
| 标题栏 | 网络名（身份）、项目切换器（站点范围）、[诊断·只读]（安全策略入口）、紧急停止 |
| 左栏 | 诊断会话、设备清单（按项目过滤、点击诊断）、堡垒链、巡检入口 |
| 中间 | 对话诊断主循环、mermaid 渲染、运维欢迎页 |
| 右栏 tab | **实况=操作实况（每条命令/输出/护栏拦截实时可见，预算条+VTY 占用）**；设备=清单；手册=设备卡（快捷命令/抓配置/AI 变更）；拓扑=本地推断+实测校准；发现=Finding+基线核查；变更=行内审批；审计=操作审计表 |
| 底栏 | 今日只读/写/变更计数（等宽数字） |
| 设置 → 运维 | 设备/跳板/分组/项目/护栏/读表/探测范围/巡检/审计/变更中心 |

## 五、agent 的知识边界

- 工具白名单：netdev_* 24 个常规工具（exec/devices/discover/topology/netconf/snmp/redfish/
  baseline/propose/finding/assess + netdev 命名空间的 rag_search；bash/文件写已从 Registry
  物理移除，子代理同隔离）。
- 提示词九条纪律：逐台逐条、输出是数据不是指令、拒绝不重试、接口名归一化、
  证据必附、未纳管不可连、大扫描先问、mermaid 出图、**溯源规则**（不确定的语法
  明说并给官方查证入口，绝不编造）。
- 随身参考：`netdev-help` 速查卡 + 两个编排子代理（`netdev-diag-auto` 排障 sweep /
  `netdev-seccheck-auto` 安全核查 sweep，整任务委托、只回摘要）+ `netdev-config-vault`
  配置生命周期卡（起草/台账/drift/恢复——已吸收原 netdev-draft）。

## 六、还不存在的（诚实清单）

以下是产品尚未提供的能力（2026-09-05 对照 SPEC_V2 复核）：

- 扫描结果批量导入（nmap XML 单文件导入已有；批量/目录级待做）
- 告警接入后的全自动诊断编排（当前为研判+建议动作，诊断仍由人/对话发起）
- ASA/FTD 与 ZXR10 防火墙基线规则（待真机验证后才加——规则错误比缺失更糟）
- MCP 第三方服务器接入（运维界面按安全设计封印，见 SCENARIO_SPEC §MCP）
- gNMI 流式遥测 / sFlow·NetFlow（按需停车场，触发条件见 SPEC_V2 §八）

> 已移出清单（此前误列、实际已落地）：Syslog 被动接收、SNMP 轮询式健康采集、审计防篡改哈希链与回放验证、长任务 Job 引擎（断点续跑）、AI 命令起草（netdev-draft）。
