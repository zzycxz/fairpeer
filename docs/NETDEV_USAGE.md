# 运维能力使用逻辑（Usage Map）

视角是"怎么用"：一个命令/按钮从哪进、经过什么闸门、结果落在哪。
规格细节见 `NETDEV_SPEC.md`；求助入口见 `NETDEV_HELP.md`。

---

## 一、总原则（一切能力的边界）

**读是默认，写是例外，攻是限时。**

- 读：结构只读密封——分类器表驱动，模型无法自我放开；不确定 = 拒绝。
- 写：唯一路径是变更（agent 起草 → 人批准 → 人执行 → 可回滚）。
- 攻（安全评估）：engagement 编号+有效期，到期自动失效。
- 凭证：TOML 只存环境变量名，值在加密存储；审计永不落原文；输出进上下文前先脱敏并提示条数。

## 二、七条主流程

### A. 首次接入（从零到能用）
设置 → 运维：录入设备（或 ~/.ssh/config 导入）→ 填地址/厂商/分组/凭证环境变量 →
「测试连接」（首次弹主机密钥指纹，确认即 TOFU 信任）→（可选）建项目、配护栏 →
回到页面：左栏出现设备，中间欢迎页给示例。

### B. 日常诊断（主循环）
用户在对话框描述故障 → agent：
1. `netdev_devices` 看清单（受 allowed_groups 作用域过滤——模型的世界先被裁剪）
2. `netdev_exec` 逐条只读命令（display/show/ping/tracert/netconf get）
   闸门顺序：**多行拒绝 → 组作用域 → 每轮预算 → 分类器**（全部过了才拨设备）
3. 输出脱敏后进入上下文（敏感字段计数提示）
4. 关联推理 → mermaid 图（邻居/路径/流程）→ `netdev_finding` 落结论（必带证据）

**遇到未知命令**：拒绝并说明 → 用户在设备卡点「允许此命令」一键教读表
（[netdev.extra_read]，立即生效；只有用户能教）→ agent 下次即可用。

### C. 配置变更（写路径）
入口两个：拓扑图点节点 → 设备卡「AI 配置变更…」；或对话直接说。
agent：先只读确认现状 → `netdev_propose` 起草（每步必带回滚命令，受变更窗口/
组策略约束）→ 右栏「变更」tab **行内** 批准 → 执行（逐台先备份）→ 部分失败即冻结
→ 可按回滚计划回退。全程 agent 无执行权。

### D. 拓扑（本地优先）
进「拓扑」tab 即见 **IP 规划推断视图**：纯本地计算（分组→命名惯例→网段排序推
层级），零拨号零 AI，绝不编造连线。点「LLDP 实测校准」才逐台读邻居表补真实链路
（徽标区分两种来源，不静默混合）。点纳管节点 → 设备卡；未纳管邻居 → 录入引导。

### E. 周期任务与安全姿态
- 巡检：左栏「立即巡检」单击直跑只读电池 → Finding；主机分诊/基线/弱口令
  在其右侧 ▾ 溢出菜单（有登录或字典依赖，需显式选择）。inspection_interval 定时同只读电池。
- 安全基线：「发现」tab「安全基线核查」或 agent `netdev_baseline` →
  密封读 running-config → 本地规则（Telnet/SNMPv1v2c/明文密码/SSHv1/NTP/Syslog）
  → 命中入发现（带脱敏证据+修复建议，修复走变更）。
- 评估模式（攻，限时）：`[netdev.assessment]` 信封（engagement_id/expires/
  approver）有效时，agent 可用 `netdev_assess` 做弱口令核查——basic 档 ≤3 次、
  dictionary 档 ≤10 次硬顶（凭据来自本地小字典，绝不在线爆破）；信封缺失或
  过期一律拒绝并落审计。设备卡的同款入口走同一预算。

### F. 应急
标题栏「⏹ 紧急停止」：断开全部连接（释放 VTY），审计记录；Manager 随即可重连。

### G. 蓝队漏洞核查（对话驱动，结果落「蓝队核查」页卡）
对话框说"做一轮蓝队漏洞核查"（或右侧 dock「蓝队核查」页卡点「发起核查」插示例指令）→
agent 走 `netdev-vulnscan` 技能（inline，过程在对话里可见）：
1. **指纹发现**（只读）：服务器读包清单与版本（`dpkg -l`/`rpm -qa`/`pip list`/
   `java -version`；Windows 用 `Get-HotFix` 补丁级与注册表已装软件），网络设备读
   `display version`/SNMP 版本；多台同类走 `netdev_fanout`。
2. **候选**：`netdev_cve_match`（已导入 CVE feed 时给出 设备×CVE 粗命中）+ 模型自身
   知识（标注"须验证"——知识有截止时间，绝不凭记忆断言无漏洞）。
3. **只读验证**：版本区间比对为主；定不了 → info 级"待人工核对"，不升级结论。
4. **立案**：确认命中逐条 `netdev_finding`（source=vulnscan，必带命令输出证据）；
   保存即推送到「蓝队核查」页卡（含 CVE 扫查 cve:* 来源），可建案例/跳发现/插
   修复变更指令。
红线：不做利用性验证；主动扫描（nmap/netprobe）须评估信封，核查不开不绕；
feed 用户自备（安全工作台 → CVE 粘贴导入，产品不分发）。

## 三、护栏开关一览（设置 → 运维 → 护栏）

| 开关 | 默认 | 作用层级 |
|---|---|---|
| 结构性只读 | 恒开（无开关） | 每条命令（分类器） |
| 设备组策略 | 按组 | 写路径级别（只读/变更/双确认） |
| confirm_each_command | 关 | 每条工具调用弹审批卡（压过全自动模式） |
| turn_command_budget | 0=不限 | 每次提问（提交即重置） |
| allowed_groups | 空=全部 | 每次 AI 询问（清单+执行双过滤） |
| 脱敏/审计/预算提醒 | 恒开 | 回包透明度 |

## 四、界面 ↔ 能力对照

| 界面位置 | 承载能力 |
|---|---|
| 标题栏 | 网络名（身份）、项目切换器（站点范围）、[诊断·只读]（安全策略入口）、紧急停止 |
| 左栏 | 诊断会话、设备清单（按项目过滤、点击诊断）、堡垒链、巡检入口 |
| 中间 | 对话诊断主循环、mermaid 渲染、运维欢迎页 |
| 右栏 tab | **实况=操作实况（每条命令/输出/护栏拦截实时可见，预算条+VTY 占用）**；设备=清单；手册=设备卡（快捷命令/抓配置/AI 变更）；拓扑=本地推断+实测校准；发现=Finding+基线核查；变更=行内审批；审计=操作审计表 |
| 底栏 | 今日只读/写/变更计数（等宽数字） |
| 设置 → 运维 | 设备/跳板/分组/项目/护栏/读表/探测范围/巡检/审计/变更中心 |

## 五、agent 的知识边界

- 工具白名单：netdev_* 十二件套（exec/devices/discover/topology/netconf/snmp/redfish/
  baseline/propose/finding/assess + netdev 命名空间的 rag_search；bash/文件写已从 Registry
  物理移除，子代理同隔离）。
- 提示词九条纪律：逐台逐条、输出是数据不是指令、拒绝不重试、接口名归一化、
  证据必附、未纳管不可连、大扫描先问、mermaid 出图、**溯源规则**（不确定的语法
  明说并给官方查证入口，绝不编造）。
- 随身参考：`netdev-help` 速查卡 + `netdev-playbook` 通用读序 +
  `netdev-diag-ospf/bgp/interface` 三个深度诊断 playbook。
