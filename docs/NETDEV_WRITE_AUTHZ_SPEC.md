> 日期：2026-09-07。状态：设计定稿，待实施（落地批次见 §11）。
> 本 spec 修订 NETDEV_SPEC §7.1 的"结构性只读"原则；落地前 §7.1 现行文本继续有效。
> 关联文档：NETDEV_SPEC.md（被修订）、NETDEV_USAGE.md（操作手册，随 P1 同步；
> 前端 guides/NETDEV_USAGE.md 同步副本）、SKILL_ARCHITECTURE_SPEC.md /

## 0. 结论摘要

1. **原则修订**：封印的是"写"，不是"自主性"。读保持并加强自治（诊断/核查的
   整任务委托子代理属技能体系轨道）；写从"全部只走提案"修订为**两把锁分级受控直写**。
2. **两把锁**：锁 1 = 对话模式（变更询问/自动编辑/完全访问），会话姿态，
   **只能收紧不能放宽**；锁 2 = 设备写档（sealed/confirm/auto），授权地基，
   **Manager 层强制**（会话无关，无人值守同样生效）。写路径生效规则 = 两锁取严（AND）。
3. **接入必配锁**：手动添加向导、发现转正对话框、工作区创建三个入口强制选锁；
   默认 sealed（零值即安全）；设备级覆盖只许收紧。
4. **放宽必告警确认**：任何放宽方向的档位切换（sealed→confirm、sealed→auto、
   confirm→auto）每次弹独立告警确认——风险明示 + 确认仪式（auto 档输设备名）+
   审计落链；手改 TOML 绕不过（已确认锁状态存档，未确认的放宽按 sealed 降级加载并告警）。
5. **AI 无开锁路径**：工具面不存在改锁工具，提案步骤类型无 set-tier——AI 可以执行
   被授权的写，但打不开自己手上的锁。锁是给人的，告警确认也是给人的。
6. **受控写三明治**：每条直写 = pre 快照 → 单条执行 → post 快照 → 自动 diff →
   审计；独立写预算（turn_write_budget）；任何一步失败即停，写前状态必已在库。
7. **自动备份与操作台账**：定时快照（scheduler → RunBackup）+ 事件快照（三明治
   pre/post、提案执行统一落 vault）+ drift 看护（快照 diff 自动立案）。存储 =
   **vault 运行时权威 + git 镜像审计层**（可选开关，缺 git 优雅降级）。**操作台账
   （OpStep）**把每次写步编成可检索时间线（谁/何时/哪台/什么命令/diff/回退指针），
   支持**单步 / 会话 / 时间点三粒度回退**——每一步可保存、可追溯、可回退。
8. **硬底线不变**：dangerous 类任何档不可直写；unknown 类永远拒；restore 永远提案；
   scopes/组隔离/审计链/脱敏全档照旧（§8 全文）。

## 1. 背景与原则修订

### 1.1 原 §7.1 的保留部分

双向密封的两张表继续有效（netdev_* 仅在 netdev profile 注册；netdev 无 bash/文件写）。
分类器三态（read/write/dangerous/unknown）表驱动、模型无法自我放开——**保留且仍是
本 spec 的地基**：写档放行发生在分类器判定之后，不是替代分类器。

### 1.2 修订动因

- 实验室/测试设备需要 AI 直写能力（靶场闭环、配置实验、教学演示）；
- "过程可见"不构成拒绝直写的理由——主循环/子代理的 transcript 与事件流已提供
  实时可见性；
- 提案管道（proposal.go）已内置 backup→apply→冻结语义、在线人员检查、变更窗口、
  二次确认、回滚计划——受控直写**复用同套控制件**，不是从零造写通道。

### 1.3 修订的表述

原："写：唯一路径是变更（agent 起草 → 人批准 → 人执行 → 可回滚）。"
修订后："写：按设备写档分级——sealed 走变更（默认），confirm 逐条审批直写，
auto 直写并自动快照；两把锁取严，硬底线不可档位解锁。"

## 2. 两把锁模型

### 2.1 锁 1：对话模式

- 值：变更询问（默认）/ 自动编辑 / 完全访问（ApprovalModeSwitcher）。
- 机制：permission 层 writer 回退决策；**Ask 规则高于完全访问**是既有先例
  （confirm_each_command 的设计注释："网络是每条命令都必须是控制点的地方"）。
- 语义：本次会话"要不要多问我"。对设备写**只能单向收紧**，永远不能放宽。

### 2.2 锁 2：设备写档

- 值：sealed / confirm / auto（§3）。
- 机制：Manager/分类器层强制，会话无关——headless/定时任务（permission Ask
  自动放行以保自治的场景）也绕不过。**权限层是 UX，不是防线。**
- 语义：这台设备"被授权"什么写路径。只能被配置改变（郑重、有审计的动作），
  不能被会话改变（随手、为别的目的做的动作）。

### 2.3 合成矩阵（取严）

| 设备档（锁2）↓ / 对话模式（锁1）→ | 变更询问 | 自动编辑 | 完全访问 |
|---|---|---|---|
| sealed（生产） | 提案 | 提案 | 提案 |
| confirm（受控） | 弹卡 | 弹卡 | **弹卡**（锁2硬规则 > YOLO） |
| auto（实验室） | 弹卡（锁1收紧） | 直连 | 直连 |

关键性质：**任何一把锁单独被打开，都不足以导致写。** 无意识 Ctrl+Y 只影响锁 1：
生产（sealed）无变化、受控（confirm）仍逐条卡、实验室（auto）仅减少提示且
三明治照跑。

### 2.4 实现位置分层

| 层 | 住什么 | 为什么 |
|---|---|---|
| Manager/分类器 | 锁 2 enforcement、三明治管线、写预算、审计 | 防会话级与无人值守绕过 |
| permission | 锁 1 合成（auto 档的写调用按 writer 走模式回退） | UX 层；Ask 高于 YOLO 的合成在此完成 |

## 3. 锁 2 三档定义

| 档 | 行为 | 硬规则（锁1不可逾越） | 结构性安全网 | 适用 |
|---|---|---|---|---|
| sealed（默认） | 写只走提案管道 | 无直写授权 | 提案全套（备份/窗口/审批/回滚/观察期） | 生产 |
| confirm | 写命令直连，逐条审批卡 | 每条必审（完全访问下仍弹） | 三明治 + 写预算 + 审计 | 预生产/受控网 |
| auto | 写命令直连 | —（可配时间盒回落） | 三明治 + 写预算 + 审计 + 可选 expires | 实验/靶场 |

## 4. 锁的挂载与接入

### 4.1 三层挂载

```
[netdev.write] default_tier = "sealed"   ← 全局默认（出厂底线）
  └─ 组/工作区 write = …                  ← 工作区入口设默认锁，成员继承
       └─ 设备 write_override = …         ← 只许收紧、不许放宽
```

与既有 `NetDevGroup.Policy`（提案确认行为：只读/变更/双确认）**正交**：
Policy 继续管提案管道，write 字段只管直写通道。

### 4.2 接入入口强制过锁

| 入口 | 行为 |
|---|---|
| 运维设置 → 添加设备（手动接入） | 向导含写档步骤，sealed 预选，不选不让存 |
| 发现中心 → 待确认区 → 转正（主要接入路径） | 转正对话框必选写档，sealed 预选 |
| 新建工作区/组 | 设默认锁 |

### 4.3 存量迁移与加载校验

- 存量设备零动作落 sealed（= 今日行为，无漂移）；
- **加载校验**：清单中无写档的设备**拒绝加载**并报配置错误，而不是默默当
  sealed——默默当会让配置漂移不可见。

### 4.4 UI

- 设备卡与工作区头部**常驻锁徽标**（🔒 sealed / 🔐 confirm / ⚡ auto）——
  运维一眼知道自己在对什么档位的设备说话。

## 5. 放宽告警确认

### 5.1 触发规则（方向性判定）

基准 = **已确认锁状态**（状态目录存档），非本次配置值。放宽方向（sealed→confirm、
sealed→auto、confirm→auto）**每次必弹**，不提供"不再提示"；收紧方向（含时间盒
到期自动回落）静默生效。

### 5.2 告警确认三要素

1. **风险明示**：告警卡写清语义变化（"设备 sw1 将允许 AI 直接执行写命令
   （sealed → auto）。生产环境请确认该设备确属实验室/可写范围。"）；
2. **确认仪式**：auto 档输入设备名（或等价双重确认）；confirm 档点击带风险文案按钮；
3. **审计落链**：谁、何时、确认了哪条风险提示、从何档到何档——事后追查
   "当时谁知道这台设备被开写了"，答案就在这条记录里。

### 5.3 TOML 防绕过

- 状态目录存 confirmed lock state（每台设备最近一次经告警确认的档位）；
- 配置加载时比对：放宽方向且无对应确认记录 → 该设备按 **sealed 降级加载** +
  界面弹出一次性告警（"检测到 sw1 写档被改为 auto，未经确认——已按只读处理，
  确认请到运维设置重新操作"）；
- 效果：**配置文件只是申请书，生效必须过一次人的告警确认**——无论从哪个入口改锁。

### 5.4 不变量：AI 无开锁路径

- 工具面无 set-tier 工具（主循环、子代理均无）；
- 提案步骤类型枚举不含写档变更；
- 锁放宽的确认动作只能来自运维设置 UI（人）。

## 6. 受控写管线（三明治）

```
写命令（分类器=write，锁2放行，dangerous/unknown 先拒）
 → ① pre 快照：backupCommand(drv)（华为 display current-configuration /
    思科 show running-config）→ vault 新版本（tag: pre，关联本轮/命令）
 → ② 执行单条（confirm 档此处弹审批卡；不批量）
 → ③ post 快照 → vault 新版本（tag: post）
 → ④ 自动 diff pre↔post → 回给模型（实际变更行）+ 审计链
 → ⑤ turn_write_budget 计数（默认建议 10，独立于读预算）
 → ⑥ OpStep 落操作台账（§7.3：含 pre/post 快照指针与回退指针）
```

- **任一步失败即停**——停在哪，写前状态都已经在库；
- 在线人员检查复用提案的 preExecOnlineCheck；
- confirm 卡走 **Manager 自己的审批通道**，不注册成 permission Ask——完全访问
  跳过的是 permission 系统，触不到这层（即使实现上复用 Ask 规则，Manager 层
  再校验一次审批凭证，双保险）。

## 7. 自动备份与操作台账

### 7.1 三个来源

| 来源 | 触发 | 落点 |
|---|---|---|
| 定时 | `[netdev.backup] interval`（可按组覆盖）→ scheduler → RunBackup | vault |
| 事件 | 三明治 pre/post；提案执行快照统一落 vault（今日只存提案 JSON 内，统一进 vault 才有跨变更连续历史线） | vault |
| drift 看护 | 定时快照 vs 上一版 diff，差异自动立案 finding（"sw1 配置于 X 时点变化，非变更窗口"）——持续回答"谁改了什么" | finding |

### 7.2 存储选型：vault 权威 + git 镜像

- **vault 保持运行时权威**：restore 正确性不依赖外部 git 二进制存在；原子写/
  单调 ID/Windows 文件锁语义已验证；list/diff/restore 工具面围绕它建成。
- **git 镜像审计层**（`[netdev.backup] git_mirror = true`，可选）：每次 saveBackup
  顺手 commit 每设备明文 config（commit message 带触发源 scheduled /
  proposal:ID / pre-write）——白拿三样：内容寻址去重（每日全量快照不膨胀）、
  blame 式审计（哪行哪次改的）、人类可读历史（`git log -p` 直接看演进）。
- **缺 git 二进制 → 跳过镜像**，vault 不受影响，优雅降级。

### 7.3 操作台账与分步回退

原则：**每一步可保存、可追溯、可回退。** 三明治产生的 pre/post 快照天然就是
"恢复点"——台账把它们编成时间线，并给出回退动作位。这是用户侧的核心诉求：
操作能做、流程有指导、每步有存档、回退要方便。

**记录模型（OpStep）**——每次写动作（直写 / 提案步 / 回退本身）落一条：

| 字段 | 内容 |
|---|---|
| id / 时间 | 单调 ID，精确到设备 |
| 操作者 | agent 轮次 / 用户手动 / 定时任务 |
| 设备 + 动作 | 命令原文或提案步骤 |
| 快照指针 | pre / post 两个 vault 版本 ID（三明治产物） |
| diff 摘要 | 实际变更行 |
| 关联 | finding / proposal / 委托批次（可追溯"为什么改"） |
| 回退指针 | restore_from = pre 版本 |

**回退三粒度**：

| 粒度 | 动作 | 通道 |
|---|---|---|
| 单步回退 | 台账上"回退此步"= restore(pre 版本) | **按设备写档走通道**：auto 直连、confirm 弹卡、sealed 提案 |
| 会话/批次回退 | 本会话（或本次委托）全部写步**逆序**回退 | 逐 step 过闸（复用割接的逆编排语义） |
| 时间点恢复 | vault 时间线任选版本 | **恒提案**（§8.3）——人指定目标版本是郑重决定 |

**不变量**：
1. **回退本身也落台账**（回退可被回退）；
2. **回退前先抓当下状态**（回退的三明治 post = 失败现场，永不丢）；
3. sealed 档的单步回退仍走提案——生产回退人按按钮，与 §8.3 同一精神；
   auto 档允许直连回退是"直写的对称撤销"，实验室语义自洽。

## 8. 硬底线（任何档位不可解锁，红测试钉死）

1. dangerous 类（reload / erase / format / delete flash…）**不可直写**；
2. unknown 类**永远拒**（先教分类表再谈写）；
3. **时间点恢复（restore）永远提案**——事故路径必须人按按钮；已知写步的
   撤销回退按 §7.3 分档走通道（sealed 档仍提案）；
4. scopes 白名单 / 组隔离 / allowed_groups 恒开；
5. 审计链、脱敏双重点（进上下文前 + 落盘前）全档照旧；
6. AI 无改锁路径（§5.4）。

## 9. 与技能体系/子代理的关系

- 锁在 Manager 层 → 一切执行路径（主循环 / 子代理 / 未来的变更执行子代理）
  同一把锁；
- 当前编排子代理（netdev-diag-auto / netdev-seccheck-auto，技能体系轨道 P1）
  工具面**纯读、不含写工具**——写留在主循环；
- 子代理工具面若未来含写：同一 Manager 锁 + 桌面 Ask 桥接（`sub-agent:` 前缀
  审批卡）双保险，headless 场景由 Manager 锁兜底。

## 10. 配置示例

```toml
[netdev.write]
default_tier = "sealed"        # 出厂底线
turn_write_budget = 10         # 每轮直写条数（独立于读预算）

[[netdev.groups]]
name = "lab"
write = "auto"                 # 工作区默认：实验室直连
# auto_expires = "72h"         # 可选时间盒：到期自动降回 confirm

[[netdev.devices]]
name = "sw-lab-01"
group = "lab"
# write_override = "sealed"    # 只许收紧

[[netdev.devices]]
name = "core-sw-01"            # 未入 lab 组 → 全局默认 sealed

[netdev.backup]
interval = "24h"               # 定时快照
git_mirror = true              # 可选 git 镜像审计层
```

## 11. 落地批次

> 原则：每批的前端与后端**同批交付**——锁的语义离开确认弹窗与徽标既不可用
> 也不可见；后端先行而 UI 缺位的中间态不允许出现（宁可整批延后）。

### P1 写授权（后端语义 + 必需前端）

**后端**：
- `write` 三档配置（全局/组/设备三层挂载，tighten-only 校验）+ Manager 层 enforcement；
- 两把锁合成（auto 档写调用按 writer 走 permission 模式回退；confirm/sealed 在
  Manager 层先行决定）；
- 三明治管线（pre/post 快照 + 自动 diff + 审计）+ `turn_write_budget` 独立计数；
- confirm 档 Manager 审批通道（不依赖 permission Ask，完全访问跳不过）；
- confirmed lock state 存档 + 加载比对（未确认放宽 → sealed 降级 + 告警事件）；
- 加载校验：无写档设备拒载并报配置错误；
- **OpStep 操作台账落库**（三明治第⑥步：写步编目，数据就位）；
- 附录 A 写面盘点中"现状即合规"各行复核（HumanTTY 人专属、SFTP 提案专属）；
- §12 红测试 1-10 全绿。

**前端（P1 必需，缺则锁不可用）**：
- 运维设置：锁管理（组/设备写档编辑）+ 护栏子页教学文案（护栏表加写档行）；
- **放宽告警确认弹窗**：风险明示 + auto 档输设备名仪式 + 审计落链提示，
  每次必弹、无"不再提示"；
- **confirm 档写命令审批卡**：命令 + "将先自动抓改前快照"说明（在线人员
  提示复用提案语义）；
- **TOML 拦截告警**：未确认放宽被降级加载时的一次性横幅/弹窗；
- 接入入口：添加设备向导写档步骤、发现转正对话框写档选择（sealed 预选）；
- **锁徽标**：设备卡 / 左栏清单 / 工作区头部，hover tooltip 三档一句话语义；
- LiveOpsPanel 预算条加直写计数（读/写双条）；底栏加今日直写计数；
- i18n：以上全部文案 zh/en 双语。

### P2 自动备份

**后端**：定时快照（`[netdev.backup] interval` → scheduler → RunBackup，可按组
覆盖）；提案执行快照统一落 vault（今日只存提案 JSON 内）；git 镜像（可选开关、
缺 git 优雅降级）；drift 看护（定时快照 vs 上一版 diff → 自动立案）；
**会话逆序回退执行器**（本会话写步逆序 restore，逐步过闸——复用割接逆编排）。

**前端**：设备卡**备份时间线视图**（版本列表 / 任意两版 diff / 与现网 drift
入口；空态复用 PanelStates 三要素）；**操作台账视图**（时间线 + 每步 diff +
单步"回退此步"按钮 + 会话"回退本次全部写"入口；与备份时间线同屏相邻）；
发现 tab 的 drift 来源行展示；设置页备份开关（interval + git_mirror）。

## 12. 验收红测试清单

1. 完全访问 × confirm：写命令仍弹卡；
2. 任意模式 × sealed：写命令仍路由提案；

   （Manager 层不依赖 permission）；

## 附录 A：写面盘点（锁覆盖矩阵）

**唯一写通道原则**：任何能改变设备状态的路径，终点必须是同一个 Manager 闸门
（分类器 → 写档 → 三明治）。不允许存在绕过该闸门的第二写通道。

| 写面 | 现状 | 锁的处理 |
|---|---|---|
| `netdev_exec`（CLI 写） | 分类器拒写 | 本 spec 主体：三档放行 + 三明治 |
| `netdev_netconf` | 只读 RPC（`<get>`/`<get-config>`），edit-config 拒 | 未来开放写 RPC 时同锁同三明治（快照即 running-config） |
| `netdev_snmp` | 仅 GET/WALK，无 set 路径 | 若未来加 set：同锁；倾向永不开放（配置走 CLI/NETCONF） |
| `netdev_redfish` | 仅 GET（硬件/温度/SEL） | 未来电源控制/虚拟介质等硬件写：至少 confirm 档 + 审计；硬重启类归 dangerous |
| SFTP | 仅 Download/Browse（读）；上传只在提案 `StepFileUpload` | v1 保持提案专属；未来直传需写档 + 前后状态捕获 |
| 结构化提案步骤（k8s apply / sql migration / cert replace / file upload） | 仅人工批准的提案可执行 | **所有档位保持人工批准**——写档管直连通道，不自动批提案 |
| 提案执行 / 回滚 | 人批准后执行 | 恒人工门——auto 档也**不**解锁提案自动执行 |
| restore（备份恢复） | 提案专属 | 时间点恢复恒提案（§8.3）；已知写步的撤销回退按 §7.3 分档 |
| `netdev_remote`（fleet 委托） | 只读资源（health/triage）+ 能力令牌 + fleet PAUSE 刹车 | 未来写资源：目标主机写档 + 能力令牌双重门 |
| HumanTTY / 串口 console | 人接管通道（桌面桥），agent 无工具可达 | **保持人专属**；若未来给 agent 开输入路径，必须过同一分类器 + 写档——否则即旁路，禁止 |
| docker / k8s / db 工具 | 只读（清单/健康/allowlist 查询） | 目标本就是清单设备——未来任何写操作自然落同一把设备锁 |
| 割接（cutover） | 编排**已批准**提案，从不批准 | 恒人工门 |
| 评估 `netdev_assess` / 测绘 `netdev_probe`（合并原 discover/nmap/netprobe） | 非写；攻的锁（评估信封 + scopes）已覆盖 | 与写锁并行、互不替代（读/写/攻三锁各守一门） |
| 通知 / 升级（notify / escalate） | 外发消息，非设备写 | 走既有外部风险权限类，不入本锁 |
| 备份库写入（saveBackup） | 系统自身受信路径 | 三明治/定时/提案的落点，非 agent 面 |

分界一句话：**写档只管"直连通道"的放行姿势；提案管道与 restore 在任何档位都
保持人工门。** 未来任何新增的设备触达能力（新工具、新协议、新通道）立项时，
本表必须先加一行、定好锁的处理，才允许进实现。
