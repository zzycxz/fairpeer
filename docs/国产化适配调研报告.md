# fairpeer 国产操作系统（统信 UOS / 银河麒麟）适配调研报告

日期：2026-09-09 · 调研方式：三轮 × 三个子任务（共 9 项调研，含代码审计、外部生态调研、交叉验证）

---

## 一、总体结论

**可以适配，且底子比预期好，但"当前发布产物"在 UOS/麒麟上跑不起来——需要新建构建与分发腿，并补齐一批中小型适配项。**

| 层面 | 结论 |
|---|---|
| Go 内核（`fairpeer` CLI / serve，CGO_ENABLED=0 纯静态） | ✅ **零改动可用**。已实测 `GOOS=linux` 下 amd64 / arm64 / loong64 三架构编译通过；代码中所有 Windows API 都规范隔离在 `_windows.go / _other.go` 文件对里，无一处未隔离的 Win32 调用 |
| 桌面 GUI（Wails v2.13 + WebKitGTK） | ⚠️ **x86_64 + arm64 桌面版可行，但需专门构建**。当前 release.yml 用 `-tags webkit2_41`（WebKitGTK 4.1）+ Ubuntu 24.04（glibc 2.39）编译，而 UOS 20 / 麒麟 V10 桌面版只有 WebKitGTK 4.0 且 glibc 2.28——现有 Linux 发布包装不上、跑不了。Wails v2.13 默认（无 tag）构建恰好就是 4.0，改构建环境即可 |
| 龙芯 loong64（3A5000/3A6000 新世界） | ⚠️ **实验性可行**。Go 内核 OK；Wails 官方不支持 loong64（issue #3697 not-planned），但新世界系统（Loongnix 25 / Debian ports）有 WebKitGTK 4.1，可原生构建 `-tags webkit2_41` 版本；无现成 CI，需 3A6000 实机（约 ¥2,000–4,000）自建 |
| 麒麟 V10 服务器版（RPM、无图形环境） | ✅ 走 **`fairpeer serve` + systemd 无头部署**，正好匹配服务器版运维习惯；不要尝试 GUI |
| mips64el（老龙芯 3A4000）、旧世界 loongarch64（麒麟 V10 SP1-SP3 全部）、申威 sw64 | ❌ **不可行，明示不支持**。mips64el 上 modernc.org/sqlite 编译失败（已实测）；旧世界 ABI 无法运行 Go 1.19+ 二进制（静态也不行）；sw64 无上游 Go 支持 |

**一句话路线**：以"内核先行、桌面跟进、龙芯实验、服务器无头"为策略，先交付 x86_64+arm64 的 CLI + 桌面 deb，同步做离线化与信创认证。

## 二、为什么底子好（现状盘点）

1. **平台抽象严格**：66 处 build tag 全部成对（`dpapi_windows.go`/`dpapi_other.go`、`kill_windows.go`/`kill_other.go`、`pty_windows.go`/`pty_stub.go` 等），交叉编译已验证干净。
2. **路径规范**：配置走 `os.UserConfigDir()/fairpeer`（Linux 下 `~/.config/fairpeer`），状态走 `~/.fairpeer`，缓存走 `~/.cache`，无硬编码 `C:\`（仅剩 Windows 分支内的探测与注释）。
3. **SQLite 纯 Go**（modernc.org/sqlite v1.52.0），树内已含 loong64/arm64 文件，三架构编译通过。
4. **前端纯 Web 技术**（React 19 + Vite），无任何 WebView2 专属 API；字体栈已含 Noto Sans SC 兜底；CJK 用 `Intl.Segmenter` 且有特性检测。
5. **已有 Linux 基建**：Makefile `cross` 已产 linux-amd64/arm64；CI 已有 Linux 腿；`fyne.io/systray` 托盘走 SNI（DDE/UKUI 均支持）；Linux 自更新（minio/selfupdate）已实现；**netdev 串口控制台在 Linux 已有 termios 真实现**（`internal/netdev/console_unix.go`，不是 stub）；nmap 编排用 `-sT` TCP connect 扫描，无需 root/Npcap。

## 五、合规与上架（编译之外的信创门槛）

1. **统信**：开发者实名 → 统信开发者证书；上架 UOS 商店（官方唯一分发渠道，六重检测含平台代签）；线下 deb 则需企业签名或客户开开发者模式。
2. **麒麟**：麒麟软件商店（桌面）+ `eco.kylinos.cn` 生态适配中心申请**兼容性互认证证书**（厂商自测/三方检测 → 发证）；服务器版走 rpm + 私有化"银河麒麟软件商店管理平台"。
3. **信创采购**：党政 + 8 大行业招标/验收普遍要求互认证证书；前提是中国境内法人 + 软件著作权登记。建议按"飞腾/鲲鹏 + 双 OS"先做首批互认证。
4. **测试资源**（均可免费/低成本获得）：UOS ISO（chinauos.com/resource）、麒麟试用（kylinos.cn/support/trial）、Loongnix qcow2（pkg.loongnix.cn）、QEMU loongarch64（≥7.1）+ qemu-system-aarch64 功能级测试、阿里云有麒麟/统信云镜像、GitHub 免费 arm64 runner。

## 六、风险清单（按威胁排序）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 老版 WebKitGTK（2.26–2.38）对新前端特性的兼容性 | 渲染/交互异常 | 目标系统实测清单化（第五节 QA 项）；必要时降级 CSS 特性 |
| Kylin V10 arm64 曾有 Wails IPC 崩溃案例（wails#2657，已关闭） | arm64 GUI 稳定性 | 实机长稳测试；崩溃兜底 `WEBKIT_DISABLE_COMPOSITING_MODE=1` |
| glibc 底线 2.28 | 构建产物装不上 | buster 容器统一构建 + `objdump` 校验进 CI |
| 国产浏览器 CDP 未获官方背书 | 浏览器自动化核心功能 | 启动时 CDP 探测 + 失败明示；文档给 `browser_path` 配置 |
| KYSEC 拦截未签名子进程 | netdev/netprobe 等被安全中心拦 | 签名全覆盖 + 互认证白名单 |
| loong64 生态碎片（轮子老、Wails 不支持、无 CI） | 龙芯 GUI 成本高 | 定位实验性；GUI 问题用浏览器模式/TUI 兜底 |
| python3.7/3.8 老 Python 版本 | 新轮子装不上 | 按 distro×Python 版本预打包 wheel，不在线解析依赖 |
