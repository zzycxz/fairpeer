# 快捷截屏多图连拍（静默模式）设计规范

## 1. 背景与痛点
“快捷截屏解题”功能受限于单次截屏逻辑，对于垂直跨度较大的题目（尤其是考试场景的长卷子），单次截取无法覆盖完整题目。
同时，考试或极简沉浸式场景中，**严禁引入弹窗、键盘输入确认或任何打断式的 UI 交互**。要求以最高效、最隐蔽的方式完成多段截图并交由大模型处理。

> 注意：捕获方式为**整屏截图**（`builtin.CaptureFullScreen`），不含框选交互——框选本身就是打断式 UI，与静默目标冲突。

## 2. 核心架构设计：3 秒静默时间窗口 + context 防抖
采用“队列防抖”状态机：连拍期间只入队不发请求，最后一次按键后静默 3 秒才统一发包。

### 2.1 用户操作流
- **按下截屏键**：截取第一部分，右下角 Toast 提示“已捕获第 1 张截图（若无后续截图，3秒后自动发送）”，开启 3 秒倒计时。
- **向下滚动并再次按下**：截取第二部分，重置 3 秒倒计时，追加第二张图，提示“已捕获第 N 张”。
- **停止操作**：3 秒内无新按键，定时器唤醒，队列打包发送；多张时先在本地纵向拼接为一张长图。

### 2.2 防抖的并发语义（`desktop/screenshot_solve.go`）
状态与锁：
```go
var (
    screenshotMu    sync.Mutex            // 覆盖 捕获→编码→入队→防抖换代 的全临界区
    screenshotQueue []string              // 待发 data URL 队列
    debounceCancel  context.CancelFunc    // 当前防抖会话的撤回句柄
)
```
- **撤回**：新按键在锁内调用旧会话的 `debounceCancel()`（关闭其 `ctx.Done()`），旧等待协程即刻退出，再安装新会话的 ctx。不使用 `time.Timer` 复位和世代计数。
- **归属判定**：定时器唤醒后，锁内检查 **`ctx.Err() == nil`** 判定自己仍是当前会话（`context.CancelFunc` 是函数值，Go 不允许 `==` 比较，只能比较 ctx 状态）。即使 `select` 在 timer 与 ctx 同时就绪时随机选中 timer 分支，被撤回的会话也会在锁内被 `ctx.Err() != nil` 拦下，不会误领队列。
- **顺序保证**：锁从 `CaptureFullScreen` 一直持有到入队。热键轮询协程与托盘菜单协程都可能触发入口，锁覆盖捕获阶段保证并发触发时入队顺序与按键顺序一致，且防抖协程不会把一次连拍劈成两半。
- **资源卫生**：赢得发包权的协程将 `debounceCancel` 置 nil 后调用 `cancel()` 释放 ctx；等待用 `time.NewTimer` + `defer Stop()`。

## 3. 连拍上限与自动分包
单次静默窗口最多累积 `maxScreenshotBurst = 10` 张（全屏 RGBA 拼接内存 O(N×屏幕面积)，必须封顶）。
第 11 次按键时：已入队的 10 张**立即先行发送**，新截图开启新一轮连拍，Toast 提示“连拍已达 10 张上限…”。

## 4. 本地纵向拼接（`stitchImagesVertically`）
将 2~N 张 data URL 图纵向拼接为一张 PNG 长图，再交给 VLM：
- **画布**：宽度取各图最大值，高度求和；背景填**白色**（透明 padding 在供应商端转 JPEG 会变黑边）。
- **尺寸上限**：任一边超过 `maxStitchDim = 8000` px（多家 VLM 供应商拒收超大图，如 Anthropic 8000×8000）时，所有图按同一比例用面积平均核（box kernel，`golang.org/x/image/draw.Kernel`）**降采样**后拼接。
- **失败语义**：任何一张解码失败即整体报错，调用方回退为多图分开发送（`provider.ImageContent` 为变长参数，天然支持）——**绝不静默丢图**。用户会看到“自动拼接失败，改为多图发送…”提示。

## 5. 多模态底座
主流视觉模型（GPT-4o、Claude、GLM 等）均支持多图输入：拼接失败时的回退路径与单图路径共用 `provider.ImageContent(prompt, images...)`。

## 6. 优势总结
- **零打扰**：没有确认对话框和修饰键门槛；唯一新增感知是单图场景 3 秒的防抖等待。
- **有界资源**：连拍张数封顶、拼接尺寸封顶，弱机器与 HiDPI 屏不会爆内存/爆请求体。
- **并发安全**：单锁覆盖全部共享状态，防抖换代靠 context 撤回，无定时器竞态、无世代锁、无静默数据丢失。
